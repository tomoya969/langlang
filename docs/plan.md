# langlang 作成プラン

- 版：v0.1（2026-10-23）
- 対象：韓国語（日本語話者向け）。将来はほかの言語にも広げる
- 位置づけ：実装前の設計と作業の全体像。Claude Code への引き継ぎにも使う

## 概要

予習なしで、ゲーム感覚の反復を続けるうちに、日常会話に困らない語彙（約3,000語、ハン検準2級あたり）まで到達できるローカルの語学アプリを作る。

- 単語は、中央の単語の意味を矢印キーで選ぶテンポ重視のゲームで覚える。
- 文は「聞いて分かる → 選べる → 書ける → 使える」の順に段階を上げて練習する。
- 単語・文・聞き取り・タイピングの記録を単語ごとに1か所で管理する。苦手な語は、忘却曲線（FSRS）に沿って重点的に出す。
- 語彙は国立国語院のリストとハン検の出題範囲の中間をとり、3つのレベルに分けて順番に学ぶ。
- 文の採点は、機械で確かめられるものを先に確かめ、決まらないときだけ AI に判定させる。

## 1. ゴールと前提

### 1.1 ゴール
- 日常会話に困らない語彙（約3,000語）まで、無理なく到達する。
- 予習をせず、繰り返すうちに自然と覚えられる流れにする。
- 苦手な語を、忘却曲線に沿って重点的に出す。

### 1.2 前提
- 学習者：ハングルは読めて発音もできるが、単語はほとんど知らない。そのため、字母を学ぶ段階は作らない。
- 動作：ローカル（127.0.0.1）で動くブラウザアプリ。使うのは自分1人。
- AI：suburi と同じく、`claude -p` 経由でサブスクリプションの利用枠を使う（API の従量課金は使わない）。

### 1.3 今回やらないこと
- 音声入力・発音の判定
- 韓国語以外の言語（ただし、言語ごとに替わる部分は分けておく）
- 公開・複数ユーザー・スマホ向けの最適化
- 多義語の2つ目以降の意味の出題

## 3. 用語

| 用語 | 意味 |
|---|---|
| レベル | L1〜L3。語彙と文法の難しさのまとまり |
| ユニット | 1つのレベルを、場面ごとに20〜30語ずつ区切ったもの |
| 面 | 1つの単語を練習する角度。意味・聞き取り・逆引き・綴り・文脈の5つ |
| 段階 | 文の練習の進み具合。0（導入）〜5（定着） |
| カード | 忘却曲線を管理する単位。単語の1つの面、または文1つ |
| 評価 | 解答の結果を FSRS に渡す値。Again／Hard／Good／Easy の4つ |
| 安定度 | FSRS が計算する「どれだけ長く覚えていられるか」の日数 |

## 4. 学習設計

### 4.1 下敷きにする原則
1. **思い出す練習**：見て覚えるより、自分で思い出すほうが定着する。出題は「答えを出す」形を中心にする。
2. **間隔を空けた反復**：忘れかけた頃に出すのがいちばん効く。次に出す日は FSRS で決める。
3. **理解から産出へ**：聞いて分かる → 選べる → 書ける → 使える、の順に負荷を上げる。
4. **4本柱のバランス**（Nation）：意味の入力・意味の産出・形の学習・流暢さを、1回の学習に混ぜる。
5. **場面でまとめる**：意味の近い語（色の名前を全部、など）を一度に教えると混同しやすい。ユニットは「カフェで注文」のような場面でまとめる。

### 4.2 学ぶ単位
- **単語**：記憶管理の中心。矢印ゲームと文の問題の両方から記録が集まる。
- **文**：単語を文脈ごと使う練習の単位。どの単語でできているかを持つ。
- **ユニット**：新しい単語はユニットの順に出てくる。

### 4.3 レベル設計

| レベル | 目安 | 語数（目安） | 累計 | 主な文体 |
|---|---|---|---|---|
| L1 やさしい | ハン検5〜4級、TOPIK 1級 | 約1,000 | 約1,000 | 해요체が中心。あいさつなどの決まった表現は합니다体も |
| L2 ふつう | ハン検3級、TOPIK 2級 | 約900 | 約1,900 | 합니다体と반말を加える |
| L3 むずかしい | ハン検準2級、TOPIK 3級 | 約1,100 | 約3,000 | 書き言葉（한다体）を加える |

**参考にした数字**
- 国立国語院の学習用語彙リスト：全5,965語（1段階982語、2段階2,111語、3段階2,872語）。1・2段階を合わせると3,093語。
- ハン検：5・4級の出題範囲が約900語、3級が840語（5級からの累計で約1,700語）。準2級の語数は未確認。
- TOPIK：1級が約800語、2級が1,500〜2,000語。

**グラデーションの作り方**
全候補に「やさしさのスコア」（6.1）を付けて一列に並べ、上から語数で区切る。レベルの中のユニットも同じ並びで作るので、L1 の最初から L3 の最後まで、難しさがなだらかに上がる。

**順番の進み方**
- 新しい単語は、L1 の最初のユニットから順に出す。L1 を出し終えたら、自動で L2 に進む。
- 前のレベルの単語の復習は、次のレベルに進んでも続く。
- 途中のレベルから始める設定も用意する（ほかの学習者・ほかの言語のため）。今回は L1 から始める。

### 4.4 単語の練習：矢印ゲーム

**画面**
- 中央に問題（単語・意味・音声のどれか）を出し、上下左右に4つの選択肢を置く。
- 単語が出たら自動で読み上げる。Space でもう一度再生する。
- Enter は「わからない」。不正解と同じ扱いにして正解を見せる（4択のあてずっぽうを減らすため）。
- 選択肢の位置は毎回入れ替える（方向で答えを覚えてしまわないように）。

**流れ**
1. 初めての単語は、まず「初見カード」を出す。単語・意味・音声（漢字語なら漢字も）を見せ、どれかの矢印キーで次へ進む。
2. 3〜5枚あとに、同じ単語をヒントなしで出す。
3. 間違えたら、正解を音声つきで1秒ほど見せ、列の最後尾に回す。
4. 列が空になったら終了する（全問正解まで続く）。
5. 1ゲームは20枚前後。その日の分が終わるまでゲームを続けて出す（途中でやめてもよい）。

**評価（FSRS に渡す値）**

| 結果 | 評価 |
|---|---|
| 不正解・わからない・時間切れ | Again |
| 正解・遅い | Hard |
| 正解・ふつう | Good |
| 正解・速い | Easy |

- 速い・遅いの基準は、最初は固定値にする（速い：1.5秒未満、遅い：4秒超、時間切れ：10秒）。記録がたまったら、自分の正解時の反応時間の中央値を基準にする（速い：中央値の0.7倍未満、遅い：1.5倍超）。
- FSRS に渡すのは、その日のその面の最初の1回だけ。最後尾に回ったあとの正解は、ゲームの終了条件には数えるが、評価には使わない。
- 初見の単語は、初見カードのあとの最初の出題で評価する。

**ダミーの選択肢**
- 同じ品詞から選ぶ。答えと同義の語、同じ綴りの別語（同音異義語）は入れない。
- 慣れるまで（その面の安定度が7日未満）は、意味の離れた語から選ぶ。
- 慣れてきたら、形や意味の近い語（사다／싸다 など）や、自分が過去に取り違えた語を混ぜる。
- 間違えたときに選んだ語は、「取り違えの記録」として残す。

**同音異義語と多義語**
- 同じ綴りの別語（배＝腹／船／梨）は、別の単語として扱う。意味を選ぶ問題では、もう一方の意味を選択肢に出さない。
- 多義語は、最初は主な意味1つだけを出す。ほかの意味は今回は出さない。

### 4.5 単語の多面管理

1つの単語に次の「面」を持たせる。面ごとに FSRS の状態（安定度・難しさ・次に出す日）を持つ。

| 面 | 練習 | 出し始める条件 |
|---|---|---|
| 意味 | 韓→日の矢印ゲーム（文字＋音声） | 初見のとき |
| 聞き取り | 音声だけを聞いて意味を選ぶ矢印ゲーム | 意味の安定度が3日以上 |
| 逆引き | 日→韓の矢印ゲーム（選択肢は韓国語） | 意味の安定度が3日以上 |
| 綴り | 意味と音声を手がかりに韓国語を打つ | 逆引きの安定度が7日以上 |
| 文脈 | 文の問題の中で出会う | 文に出てきたとき（次に出す日は持たない） |

**文の問題の結果を単語に返す**
- 「文脈」の面は記録だけを持ち、FSRS は動かさない。
- 文の問題でその単語のところを間違えたら、誤りの種類に応じて単語の面に Again を記録する。
  - 意味の取り違え → 意味の面
  - 綴り・받침の誤り → 綴りの面（まだ出していなければ記録だけ）
  - 助詞・活用など文法の誤り → 単語には記録しない（誤りのタグだけを残す）
- 文の問題で正解したときは、文脈の記録だけを残す。

**単語の状態の表示**
- 未学習 / 学習中 / 定着（出している面すべての安定度が21日以上）
- しきい値（3日・7日・21日）は設定で変えられるようにする。

### 4.6 苦手な単語

**判定**（どれかに当てはまれば苦手とする）
- いずれかの面の FSRS の難しさが7以上（1〜10の尺度）
- 直近10回の不正解率が40%以上
- 取り違えの記録が2回以上ある相手がいる
- 正解時の反応時間が、自分の中央値の2倍以上の状態が続いている

**扱い**
1. FSRS によって、次に出すまでの間隔が自動で短くなる。
2. 1日の学習に「苦手枠」（既定5枚）を設け、期限前でも矢印ゲームに混ぜる。
3. 文の問題を選ぶとき、苦手な単語を含む文を優先する。
4. 取り違えた相手を、わざとダミーに入れて見分けさせる。
5. 単語帳の画面で、苦手な単語だけを絞り込んで練習できるようにする。

### 4.7 文の練習

**文の段階**

| 段階 | 名前 | 練習 | 採点 |
|---|---|---|---|
| 0 | 導入 | 聞く → 文字と訳を見る。新しい語と文法をハイライト | なし |
| 1 | 認識 | 聞いて意味を選ぶ（4択）／韓→日訳 | 選択式／AI |
| 2 | 部分再生 | 穴埋め（狙いの語や語尾を打つ） | 機械＋AI |
| 3 | 全文再生 | 書き取り／日→韓作文 | 機械＋AI |
| 4 | 応用 | 指定の表現を使って自分で文を作る | AI |
| 5 | 定着 | ときどき書き取りか日→韓で確認する | 機械／AI |

- 正解（Good）で1つ上へ、注意つき（Hard）ならそのまま、不正解（Again）なら1つ下へ（最低は1）。
- 評価は1回目の解答で決める（自分で直したあとの正解は評価に使わない）。
- 次に出す日は、文ごとに FSRS で決める。段階は「どの練習を出すか」だけを決める。
- 導入の直後には出題しない。間に別の問題を2〜3個はさむ。

**なぞりタイピング**
- 習った文を、ガイドつきで打つ。速さ（1分あたりの字母数）を記録する。
- 流暢さの練習なので、記憶の評価には使わない。

**キーボード部品の使い分け**

| 練習 | 次のキーのガイド | 英字の表示 |
|---|---|---|
| なぞり | あり | あり |
| 穴埋め・書き取り・日→韓・綴り | なし | 設定どおり |

- 押したキーが沈む表示は、どの練習でも常に出す。

### 4.8 1回の学習の流れ（「今日の学習」）

目安は20〜25分（新出の数で調整する）。ホームの「始める」を押すと、次の順に自動で進む。

1. **単語ラウンド**（矢印ゲーム）：期限が来た単語の面＋苦手枠＋新出（既定15語/日）。面の種類は混ぜて出す。
2. **文ラウンド**：期限が来た文（段階に応じた練習）＋新しい文（既定7文/日）。
3. **産出ラウンド**：日→韓作文と応用作文を2〜3問。対象の文がまだなければ飛ばす。
4. **仕上げ**：その日に扱った文から3文を、読み上げつきでなぞりタイピング。

**決まりごと**
- 新しい文を出せるのは、文中の単語のうち、まだ見ていない語が1語以下のときだけ。
- 復習がたまりすぎたとき（既定200枚超）は、思い出せる確率の低いものから出し、残りは翌日以降に回す。
- ホームに「復習◯枚・新出◯語・目安◯分」を出す（単語カード1枚3秒、文1問30秒で概算）。

**ペースの目安**
- 新出15語/日なら、L1 が約9〜10週間、3レベル全体で約7か月。
- 新出20語/日なら、全体で約5か月。

### 4.9 フィードバックの方針
- 機械で採点できるものは、その場で返す。
- 文の問題で間違えたら、まず間違えた場所だけを示し、自分で直させる。2回目も違えば答えを見せる。
- 矢印ゲームはテンポを優先し、間違えたらすぐに正解を見せる。
- 解説は「解説」ボタンを押したときだけ作る。作ったものは保存して使い回す。
- 誤りにはタグを付けて記録する（5.5）。

## 5. 採点基準

### 5.1 判定は3段階

| 判定 | 意味 | 評価 |
|---|---|---|
| 正解 | 意味が合っていて、文法・文体・表記に問題がない | Good |
| 正解（注意つき） | 意味は合っているが、直したほうがいい点がある | Hard |
| 不正解 | 意味が違う、または意味が変わる誤りがある | Again |

### 5.2 観点

| 観点 | 見ること |
|---|---|
| 意味 | 原文の意味が過不足なく伝わっているか |
| 文法 | 助詞・活用・時制・否定・語順 |
| 自然さ | 韓国語として不自然な言い回しがないか |
| 文体 | 指定の文体（합니다体／해요体／반말／書き言葉）に合っているか |
| 表記 | 綴り・받침・띄어쓰기 |

**正解と不正解の境目は「意味が伝わるか」**

不正解にするもの：
- 意味の取り違え、訳抜け、意味が変わる付け足し
- 意味が変わる文法の誤り（時制・否定・主語と目的語の取り違えなど）
- 綴りの誤りで別の語になっているもの
- 場面に明らかに合わない文体（目上の人に반말など）

注意にするもの：
- 通じるが不自然な言い回し
- 指定と違うが、場面上は許される文体
- 띄어쓰기の誤り、意味が変わらない綴りの小さな誤り

**文体は問題の側で指定する。** 指定がないと採点の基準が揺れるため。

### 5.3 方向ごとの厳しさ
- **日→韓（作る練習）**：5つの観点をすべて見る。
- **韓→日（読み取る練習）**：意味だけを厳しく見る。日本語の言い回し・表記ゆれ・です／ます体かどうかは問わない。韓国語の丁寧さが訳から完全に消えている場合だけ注意にする。
- **応用作文**：指定の表現を使っていなければ不正解（課題を満たしていないため）。意味の通る文なら、残りは日→韓と同じ基準で見る。

### 5.4 採点の流れ
1. 答えを正規化する（Unicode NFC、前後の空白を除く、連続する空白を1つにまとめる、文末の `. ? ! 。` を除く）。
2. 模範解答か許容例に一致すれば正解。AI は呼ばない。穴埋めは空欄の許容例（`cloze[].variants`）と、文の許容例のうち空欄の語節だけが違うものを許容例にする。書き取りは読み上げた文とだけ比べる（許容例は言い方の違いなので使わない）。
3. 空白を除くと一致し、空白の位置だけが違う場合は「正解（注意つき：띄어쓰기）」。AI は呼ばない。
4. 発音どおりの形に直すと一致する（綴りだけが違い、聞こえる音は同じ。미안해요 と 미야내요、누구예요 と 누구애요）場合は「正解（注意つき：綴り）」。AI は呼ばない。
5. 過去に AI が判定した答えと一致すれば、保存してある判定（注意の中身も含む）をそのまま返す。AI は呼ばない。
6. ここまでで決まらなければ、練習の種類を問わず AI に判定させる。判定結果は答えとセットで保存し、次に同じ答えが来たら5で返す。

- 機械が決めるのは「正解」と「正解（注意つき）」だけで、不正解は AI だけが決める。1字違いでも、打ち間違い（예오）と意味が変わる誤り（있어요 → 없어요、해요 → 했어요）を機械では見分けられないため。「9割合っていれば注意」のような字数の割合の基準は使わない。
- AI の判定がぶれないよう、プロンプトは「不正解 → 注意 → 正解」の順に条件を確かめる手順と、共通の判定の例で書く。練習ごとに「何を問う練習か」と追加の条件を足す（書き取りは聞こえた語・助詞・語尾の違いを不正解に、穴埋めは答えを空欄に入れた文で判定、など）。
- 不正解のときは、理由を `comment_ja` の1文目と、理由になった誤りの `note` に書かせる。
- 文の数はハングルで書く。書き取りで算用数字で書いた答えは、AI が正解にする（採点のプロンプトの書き取りの条件）。

### 5.5 誤りのタグ
助詞 / 活用 / 時制 / 否定 / 語順 / 語彙の選択 / 받침 / 띄어쓰기 / 綴り / 文体 / 訳抜け / その他

### 5.6 AI の出力形式（JSON スキーマの中身）

```json
{
  "verdict": "correct | correct_with_notes | incorrect",
  "meaning_ok": true,
  "issues": [
    {
      "axis": "meaning | grammar | naturalness | register | orthography",
      "tag": "助詞",
      "span": "학교를",
      "note": "「〜に行く」の「に」は 에 を使う",
      "suggestion": "학교에",
      "word_id": null
    }
  ],
  "corrected": "학교에 가요.",
  "comment_ja": "意味は合っています。助詞だけ直しましょう。"
}
```

- 1回目の不正解では `issues[].span` だけをハイライトし、答えは見せない。2回目に `corrected` と `note` を見せる。
- `word_id` が付いた誤りは、4.5の決まりで単語の面に記録する。

## 6. 教材の作り方

### 6.1 語彙リスト（国立国語院とハン検の中間）

**手順**
1. **候補を集める**
   - 国立国語院の学習用語彙リスト全5,965語（txt／Excel で配布。頻度順位・品詞・段階つき）
   - ハン検の出題範囲（公式の語彙リストが手に入ればそれを使う。手に入らなければ AI に級を推定させる）
   - 現代の日常語の補完（스마트폰、카톡 など。AI に100語ほど提案させ、確認して採用する）
2. **除外する**：助詞・語尾（文法として扱う）、固有名詞、古い語。数を数える語（개、명、번 など）は残す。
3. **粗い付与（全候補）**：AI に、ハン検の推定級・品詞・語種（固有語／漢字語／外来語／混種語）を付けさせる。50語ずつ、速いモデルでまとめて回す。
4. **やさしさのスコアを計算して並べる**（下記）。
5. **語数で区切る**：上から L1 約1,000語、L2 約900語、L3 約1,100語。残りは「L4 候補」として取っておく。
6. **固定枠を入れる**：あいさつ・数詞・指示語・代名詞・基本の動詞（하다、있다 など）は、スコアに関係なく L1 の最初のユニットに置く。最初のユニットから文を作れるようにするため。
7. **ユニットに分ける**：各レベルの語を、AI に場面ごと20〜30語にまとめさせる。ユニットの順は、平均スコアの低い順。
8. **詳しい付与（今学ぶレベルだけ）**：日本語の意味、漢字表記、取り違えやすい語、同義語、場面のタグを付ける。
9. **検算**：別の呼び出しで、意味と漢字表記を確かめる。韓国語基礎辞典（日本語の学習辞典あり）と照らし合わせられるなら照らす。食い違いは「要確認」にする。

**やさしさのスコア（0〜4、小さいほどやさしい）**
- 国立国語院スコア：1段階は0〜1、2段階は1〜3、3段階は3〜4。段階の中では頻度順位で割り振る。
- ハン検スコア：5級＝0.3、4級＝0.8、3級＝1.5、準2級＝2.5、2級以上＝3.5。
- **スコア＝2つの平均**（片方しかなければ、その値）。これが「中間をとる」の中身。
- 日本語話者向けの補正（任意）：日本語の漢字語とそのまま対応する漢字語（도서관＝図書館）は −0.2。

**ハン検の級の扱い**
- 公式の語彙リスト（協会の公式ガイド「合格トウミ」などに載っているはず）が手に入ったら、推定値を公式の級で上書きする。
- それまでは推定値として扱い、データに「推定」の印を付ける。

### 6.2 単語データ
`content/ko/words.json`（1語1オブジェクト）

```json
{
  "id": "ko-w-0123",
  "lemma": "먹다",
  "pos": "動詞",
  "level": 1,
  "unit": "L1-U05",
  "order": 118,
  "meanings": [
    { "ja": "食べる", "primary": true },
    { "ja": "（年を）取る", "primary": false }
  ],
  "origin": "固有語",
  "hanja": null,
  "confusables": ["ko-w-0456"],
  "synonyms": [],
  "homographs": [],
  "tags": ["食事"],
  "tts_text": "먹다",
  "sources": {
    "nikl_stage": 1,
    "nikl_rank": 45,
    "hanken_level": "5級",
    "hanken_estimated": true
  },
  "score": 0.42,
  "status": "approved"
}
```

- `id` は一度付けたら変えない。教材を作り直しても、学習の記録を引き継げるようにするため。
- `hanja` は日本の字体で持つ（圖書館 ではなく 図書館）。
- `status` は `draft` / `needs_review` / `approved`。学習に出すのは `approved` だけ。

### 6.3 文データ
`content/ko/sentences/L1-U05.json`（ユニットごと）

```json
{
  "id": "ko-s-L1-U05-007",
  "unit": "L1-U05",
  "ko": "점심에 비빔밥을 먹었어요.",
  "ja": "お昼にビビンバを食べました。",
  "register": "해요체",
  "scene": "友達との会話",
  "tokens": [
    { "surface": "점심에", "word_ids": ["ko-w-0310"], "eojeol": 0 },
    { "surface": "비빔밥을", "word_ids": ["ko-w-0522"], "eojeol": 1 },
    { "surface": "먹었어요", "word_ids": ["ko-w-0123"], "eojeol": 2 }
  ],
  "grammar": ["-았/었어요（過去）", "-에（時）"],
  "cloze": [{ "eojeol": 2, "answer": "먹었어요", "hint_ja": "食べました", "variants": ["먹었습니다"] }],
  "variants": {
    "ko": ["점심에 비빔밥 먹었어요."],
    "ja": ["昼にビビンバを食べた。", "昼ごはんにビビンバを食べました。"]
  },
  "status": "approved"
}
```

**文を作るときの決まり**
- 使ってよい単語は、そのユニットまでに出た単語と、そのユニットの単語だけ。
- 1つの文に入れるそのユニットの単語は、1〜3語。
- 文法は、レベルごとの文法リスト（`content/ko/grammar.json`、別途作る）の範囲内。
- 文体は、4.3の表に合わせて混ぜる。
- 1ユニットあたり12〜15文。そのユニットの単語がどれも1文以上に出るようにする。

**文の検算**
- 形態素解析（Kiwi）で原形を取り出し、`word_ids` と一致するか、使ってよい単語の範囲に収まっているかを確かめる。
- 別の AI 呼び出しで、訳の意味・文体の表示・許容例が正しいかを確かめる。
- 食い違いがあれば作り直す。2回失敗したら「要確認」にする。

**許容例**（`langlang-build variants`）
- 採点は許容例と一致すれば AI を呼ばずに正解にするので、文ができたあとに、学習者が書きそうな正しい言い方を別の段階で集める。文は作り直さない。
- 日→韓の許容例（`variants.ko`）: 同じ意味・同じ文体の別の言い方。助詞や主語の省略、縮約、語順、同じ意味の別の語・語尾、あいさつなどの決まった表現の 합니다 形と 해요 形。
- 韓→日の許容例（`variants.ja`）と、穴埋めの空欄の許容例（`cloze[].variants`、1つの語節）。
- 機械で除くもの: 模範解答と同じ・空白だけが違う・発音が同じ（綴りの誤りを正解にしてしまうため。採点では注意つきになる）・数字やローマ字を含む。
- 文を作ったときの許容例と合わせて、別の AI 呼び出しで検算し、受け入れられないものを除く（誤りを正解と覚えさせないため、疑わしいものは除く）。

### 6.4 作る量と順番

| 順 | 内容 | 量の目安 |
|---|---|---|
| 1 | 全候補の粗い付与 | 約6,000語（50語ずつ、約120回） |
| 2 | L1 の詳しい付与と検算 | 約1,000語 |
| 3 | L1 の文 | 約40ユニット × 12〜15文（約500〜600文） |
| 4 | L2・L3 の詳しい付与と文 | L1 を進めながら、追いつく前に作る |

- 教材づくりは CLI のコマンドで回す。途中で止まっても、再実行すれば済んだところを飛ばして続きから進む。
- 利用枠の上限に当たったら止まる。時間をおいて再実行すれば、続きから進む。

### 6.5 要確認の扱い
- 学習者（自分）は韓国語の正誤を判断しにくいので、確認は「AI の別の呼び出し」と「辞書との照合」を基本にする。
- 画面に「要確認」の一覧を出し、2つの案のどちらを採るかを選べるようにする。

## 7. システム設計

### 7.1 技術構成（suburi を踏襲）
- **サーバー**：Python（FastAPI＋uv）。127.0.0.1 でだけ待ち受ける。
- **画面**：ビルドなしの HTML／CSS／JS。
- **AI**：suburi の `claude_cli.py` を移植する。`ask(prompt, schema) -> dict` を唯一の入口にする。
  - `claude -p --output-format json --json-schema ...` で呼ぶ。ツール・MCP・スラッシュコマンド・セッションの保存はすべて無効にする。
  - 空の一時ディレクトリで起動し、プロンプトは stdin で渡す。
  - `ANTHROPIC_API_KEY` が設定されていたら止める。`--model` を必ず付ける。Fable は使わない。
  - 失敗は短い言葉にして画面に出し、生の出力は折りたたんで残す。
- **長い処理**：suburi の `jobs.py` を移植する（同時に1つ、画面から進行を見られる）。
- **学習状態**：SQLite（`records/langlang.db`）。suburi は jsonl だが、期限の来たカードの抽出や苦手の集計が多いので DB にする。
- **忘却曲線**：FSRS（Python の `fsrs` パッケージを使う想定。API は実装時に確認する）。目標の記憶率は既定の0.9。
- **形態素解析**：Kiwi（`kiwipiepy`）。教材の検算でだけ使う。

### 7.2 用途ごとのモデル

| 用途 | 既定 | 理由 |
|---|---|---|
| 粗い付与（全候補） | sonnet / low | 量が多いので速さを優先する |
| 詳しい付与・文の生成 | opus / 既定 | 教材の質を優先する。事前に作るので待ち時間は問題にならない |
| 教材の検算 | opus / medium | 誤りを見逃さないため |
| 採点 | sonnet / low | 学習中なので速さを優先する |
| 解説 | opus / medium | 誤りを教えないよう正確さを優先する。保存して使い回す |

- どの用途も `LANGLANG_<用途>_MODEL` / `LANGLANG_<用途>_EFFORT` で上書きできるようにする。

### 7.5 学習状態のテーブル（案）

### 7.6 読み上げ
- `speak(text, { lang, rate })` の1か所から呼ぶ。中身は Web Speech API（`speechSynthesis`）。
- 起動時に声の一覧から `ko-KR` を探す。一覧は遅れて届くことがあるので、`voiceschanged` も待つ。見つからなければ画面に警告を出す。
- 次のカードに移ったら、前の読み上げは止める。
- 速度は0.75倍と等倍を切り替えられるようにする。文の中の単語をクリックすると、その単語だけを読む。
- 声の質は OS とブラウザで変わる。足りなければ、`speak()` の中身だけを差し替える。

## 8. 画面

0. **ポータル**（`/`）：言語ごとのカードから言語を選ぶ。右上に設定（2026-10-24 追加。`docs/design.md`）。
1. **ホーム**（`/{言語}`）：今日の学習（復習◯枚・新出◯語・目安◯分）、レベルごとの進み（L1 ◯／1,000語など）、苦手の数、「始める」ボタン。
2. **学習**：単語 → 文 → 産出 → 仕上げ の順に自動で切り替わる。画面下にキーボード部品を置く。
3. **単語帳**：レベル・ユニット・面ごとの状態。苦手だけの絞り込みと、そこからの練習。単語の詳細（意味・漢字・出てきた文・履歴・取り違えた相手）。
4. **要確認**：教材の食い違いを選んで直す。
5. **設定**（`/settings`）：全体の表示（テーマ）と、言語ごとの新出の数、苦手枠、復習の上限、反応時間の基準、読み上げの声と速度、キーボードのガイドと英字の表示、面を出し始めるしきい値。

## 10. テスト

- **Python**：pytest。AI は `ask` を差し込んでモックにする（本物の claude は呼ばない）。
  - 採点：正規化、完全一致、띄어쓰기だけの違い、発音が同じ綴りの違い、保存済みの判定の再利用、AI の判定の反映
  - FSRS：評価の対応、その日の最初の1回だけが評価に使われること、面を出し始める判定
  - 今日の学習：新出の枠、苦手枠、復習の上限
- **JS**：合成ロジック・打鍵列への分解・矢印ゲームの列の動き（最後尾送り・終了条件）を、画面から切り離した関数にして、Node でテストする。
- **教材**：`validate_content.py` で次を確かめる。
  - スキーマどおりか
  - 文の `word_ids` がすべて単語データにあり、使ってよい範囲に収まっているか
  - 穴埋めの答えが文の中にあるか
  - 許容例に重複がないか
  - 漢字語に漢字表記があるか
- **読み上げ**：手で確かめるチェックリスト（声が見つかる・止まる・速度が変わる）。
